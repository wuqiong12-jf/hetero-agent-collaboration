# 只读智能体的工具范围

返回[项目首页](../README.md)。

规划、核查和配置为只读的工作者应负责分析与检查。文件只读沙箱不能单独限制外部 MCP、连接器或浏览器操作。因此，从 0.6.5 起，只读执行还会收窄工具来源；需要这些能力的任务应分给配置可写的工作者，并遵守任务范围和原有审批规则。

| 能力 | 只读执行 | 可写工作者 |
| --- | --- | --- |
| 文件、命令 | 沿用只读沙箱，Codex 保留内建 shell | 沿用工作目录写入沙箱 |
| 外部 MCP／连接器 | 不使用继承的外部工具配置 | 沿用既有配置 |
| 内部子智能体 | 禁用，让协作面板管理团队与调用预算 | 沿用既有配置 |
| Codex 浏览器、桌面操作、图片生成及宿主代码模式 | 关闭并在模型运行前核验 | 沿用既有配置 |
| Harness 工作流、Ralph | 禁用 | 沿用既有配置 |
| Skills、AGENTS 说明 | 保留可读取的说明文本；不自动安装技能依赖的 MCP | 沿用既有配置 |

这里的设置只作用于插件发起的相应执行，不会改写 Codex 主聊天的全局配置，也不会替换原生项目栏、标签页、预览或定时任务。调整成员工作方式后，按新的方式创建会话；已有对话记录保留。

## Codex：先限制，再核验

只读运行先读取当前有效配置，只在内存中取得服务器名称，不把配置、凭证或地址放进日志。为每个名称设置禁用标记，同时关闭 Apps、插件、钩子、内部子智能体及其它上述功能。创建和恢复线程都应用这些局部配置。

在发送模型任务前，后台分页检查线程的功能开关和实际 MCP 状态。只要结果缺失、接口不支持、分页不完整、功能仍启用或服务器仍提供工具，就停止，不默默退回原配置。新会话不会在这个预检失败时被保存为不可恢复的空会话；旧会话恢复失败仍保留原会话标识。

不能用空 `mcp_servers` 表清空继承配置：它会被合并。本机隔离验证确认，空表仍启动模拟服务器；逐项按精确名称禁用后，模拟服务器没有启动，也没有注册工具。

这也符合官方说明中 Apps 与命令沙箱网络限制的区别，以及 MCP 服务器的独立启用设置。参见[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)与 [App Server 文档](https://learn.chatgpt.com/docs/app-server)。

## Harness：只读使用临时配置

只读运行使用新建的临时 Harness home，通过完整 `sdk` profile 初始化，保留既有文件与命令沙箱。它不加载原 home 或 profile 中添加的外部插件。可写运行继续使用原 home；原配置不迁移、不删除。正常关闭后，临时配置目录会被清理，强制结束进程时可能留下运行时临时文件。

只读补丁关闭工作流、Ralph 和子智能体工具。工作流的宿主 VM 不提供文件沙箱边界；对子智能体的限制则用于避免面板之外派生工作和额外模型调用，不把它表述为已经证明子智能体本身绕过文件沙箱。

工具清单仍可能包含 `write`、`edit` 等内建名称；是否能写入由文件沙箱和权限服务执行判断。工具来源收窄和实际文件读写限制是两项检查，不能仅凭名称或提示词认定权限已生效。

## 验证与边界

零模型检查使用独立临时目录、合成旧配置及模拟外部插件，不发送模型任务。Codex 检查实际功能状态、MCP 清单和跨进程恢复；Harness 检查真实 SDK 的工具注册及禁用结果，并与可写模式对照，还在真实空闲 agent 的作用域中确认读取成功、有效写入及编辑均被文件沙箱拒绝。Windows 文件与命令 ACL 仍使用[独立验证工具](HARNESS_WINDOWS.md)。详细结果见[本轮记录](runs/2026-10-11-tool-permissions.md)。

需要验证自己的 Harness 载体时，可在项目 Python 环境中运行：

```powershell
python scripts/verify-harness-readonly.py --bin "完整路径\deepseek-harness-sdk-runtime-win-x64.exe"
```

该工具不读取业务任务或密钥，使用合成凭证和只会拒绝请求的本机端点；不会发送 `session/prompt`。

本项目的 Codex 会话从未注册自定义动态工具。恢复接口无法清空任意外部导入会话的动态工具，因此不对这类会话作相同保证。检查也不等于新的系统级隔离，不能保证所有未来内建能力或任意并发配置变化。外部工具的实际操作与授权仍应由对应服务执行约束。
