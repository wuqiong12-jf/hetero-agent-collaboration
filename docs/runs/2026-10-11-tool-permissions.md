# 只读工具来源收窄 · 2026-10-11

版本：0.6.5。文件只读不自动限制外部 MCP／连接器，规划、核查与只读工作者也可能继承这些工具。本轮增加执行前的工具来源限制，同时保留可写成员、原生主聊天和原有界面。

## 改进

Codex 只读运行读取有效 MCP 名称，在内存中按精确名称禁用，创建／恢复线程时应用局部配置。关闭并核验 Apps、插件、钩子、内部子智能体、远程插件、技能 MCP 依赖安装、三项浏览器能力、桌面操作、图片生成与宿主代码模式，共 12 项。模型任务前分页检查实际功能与 MCP 清单，未知或不完整结果拒绝执行；没有全局配置写入，也不退回宽松配置。

新线程的预检失败不发布会话引用，避免保存一个尚无持久化历史的空线程。已有会话预检失败保留其引用。可写工作者和模型目录探测保持原调用流程。只读仍保留内建命令及可读取的 Skills／AGENTS 文本，依赖外部工具的技能不能自动安装或调用这些工具。

Harness 只读使用新临时 home，通过 full SDK 初始化，排除原 home/profile 添加的外部插件。最后应用的权限补丁关闭 7 个工作流和子智能体模块；工作流宿主 VM 并非文件沙箱边界，子智能体的关闭用于减少面板之外派生工作。可写模式沿用原 home 和工具配置，原文件不迁移、不删除。

前端只补充工作方式说明，没有增加常驻面板。使用说明见[只读工具范围](../TOOL_PERMISSIONS.md)。

## 验证

完整回归 **371 项通过、0 失败、0 跳过**；其中验证脚本包装运行了 **9 个 Python 单元用例**。新 Codex 专项 16 项，覆盖配置形状、精确名称、分页与缺项、错误脱敏、预检拒绝、恢复标识和可写兼容。执行适配器增加调用顺序及清理断言。前端类型检查、构建和插件打包成功。

首次完整回归发现旧运行时测试替身只接受持久 home；已更新它以验证新临时 home，未削弱生产规则。最终全部通过。

真实 Codex CLI 检查没有发送模型 turn：

- 合成配置的 `mcp_servers: {}` 仍启动模拟写工具服务器，证明空表无法移除继承项；按 `sentinel.dot` 精确名称禁用后，模拟服务器新启动为 0、状态 disabled、工具为空。
- 最终生产 helper 在本机线程中确认 12 项全部关闭，`shell_tool` 保持开启，MCP 清单符合限制。
- 干净配置的服务器数量为 0，仍可通过核验。
- 隔离配置创建线程、注入一条合成原始历史并退出，另一个控制进程恢复相同 thread ID 后通过生产 helper；合成历史已持久化。没有把空 durable 线程无法恢复当成推理历史恢复失败。

真实 Harness SDK `0.1.5rc1` 与现有修复 EXE 检查同样没有发送模型输入：

- 只读清单 18 项，可写对照 27 项。两个合成旧 home/profile 插件只在可写对照加载；只读任一插件启动都被视为失败。
- 7 个禁用工具在可写对照全部存在，只读全部不存在，实际派发均返回 `UNKNOWN_TOOL`。
- 创建无模型任务的真实空闲 agent，先读取合成文件，再用正确参数执行 `write`、`edit`。读取成功，两项写入均明确 `FS_SANDBOX_DENIED`，原字节保留；参数错误或缺上下文不算通过。
- 拒绝型本机提供方服务收到请求为 0，模型任务输入为 0。临时 home 与所有自有测试目录已清理。

脚本为[零模型工具验证](../../scripts/verify-harness-readonly.py)。它补充现有[Windows ACL 验证](../HARNESS_WINDOWS.md)，没有重建运行时或把静态指纹检查称为功能证明。

## 实际部署

安装前后台 0.6.4 为 live/paused、四项任务，执行和清理空闲，磁盘与内存一致。只停止确认身份的本项目后台，再启动 0.6.5，无需迁移状态。

恢复后协作标识、目标、草稿、已确认委托、模式、监工、团队、任务、消息、会话、归档、预算、用量与目录绑定逐项摘要一致；仍为 paused、四项任务，持久化一致、没有执行。Codex 与 Harness 连接可用，继续沿用修复运行时，本轮未启动业务协作或增加业务推理调用。

插件安装成功，仅更新其界面缓存版本。临时控制连接确认 MCP connected、图标、7 项工具及 0.6.5 的两个界面资源；没有启动模型。提交上传以 Git 记录为准，正在使用的宿主窗口没有自动操作。

## 边界

只读工具来源限制与文件沙箱分别执行，SDK 工具清单可能仍包含写入入口，不能声称所有工具都无副作用。Codex 恢复协议不能清空任意外部导入会话的动态工具；本项目现有会话没有注册它们。本轮也不证明所有未来内建能力、任意配置热更新或新的系统权限机制安全。`code_mode_host` 已确认关闭，但没有将它未经证明地描述成已存在的文件沙箱旁路。正常关闭会清理 Harness 临时 home，强制终止可能留临时文件。
