# 原生主聊天需求教练接入 · 2026-10-11

版本：0.6.0。把原生 Codex 主聊天中整理目标的过程接入任务委托书，减少手动搬运五字段内容。用户仍在面板核对保存版、运行目录和预算，再确认执行。

## 交付范围

- 增加公共 `get_task_brief` 和 `save_task_brief` 工具，前者只读草稿及缺项，后者只保存五个文本字段，不确认或派单。
- 保存同时核对 `expectedStateId` 和草稿 `expectedRevision`，防止陈旧提交覆盖别的协作状态或保存版本；旧界面保存仍兼容。
- 保存成功必须匹配本次 POST 的会话、字段原文、新版本和未确认标记。409 交由用户对比，503 或回执丢失只报告不确定，先读取核对且不自动重发。
- 公共结果只含草稿及必要摘要，不返回消息、任务输出、活动目标、用量、设置和原始错误。读取团队时两次服务上下文都校验标记及协议。
- 在任务书添加默认折叠的整理请求，带入当前本地想法。用户复制到原生主聊天讨论；问题未决定时保留，保存后回到面板重新载入并预览。
- 本地编辑与主聊天保存版发生更新时提示核对，载入前保留本地备份；预览继续拒绝未解决问题。剪贴板不可用时可手动复制显示的请求。

原生主聊天的讨论使用当前聊天模型。插件没有另行在后台自动开启多轮教练，读取、复制和保存本身不触发推理。模型如何追问以及讨论质量仍需实际任务评估，不把模拟字段保存称为模型已经完成需求分析。
