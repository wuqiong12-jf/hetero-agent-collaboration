# 后台启动与关闭可靠性 · 2026-10-11

版本：0.5.3。本轮处理后台启动、端口竞争、关闭期间迟到操作，以及原生插件误连本地服务的问题。目标是保留已有任务、交付和用量，避免失败启动覆盖快照，或服务关闭后异步操作继续派单。

## 实现范围

- 服务自行管理的协作引擎在 HTTP 端口绑定成功后才创建和恢复状态。同端口竞争中收到 `EADDRINUSE` 的失败实例不读取或写入持久快照。
- `close()` 幂等返回同一个可等待的 Promise，结束 SSE 并等待 HTTP 服务关闭、执行清理和保存结果。订阅与心跳在停止后不再写入已结束的响应；清理或保存无法确认时报告失败并保留已有屏障。
- 引擎在异步渠道和模型预检、保存完成后重新检查关闭状态。关闭期间返回的迟到结果不能继续改变已关闭快照、启动模型或恢复调度。
- `/api/context` 增加 `service: 'relay-agent-workbench'` 与整数 `protocolVersion: 1`，保留实际工作目录和发布版本。
- 原生插件在访问业务接口前读取并核对服务标记、协议、工作目录和版本。可达的其他服务、缺少标记的旧后台、不兼容协议、HTTP 错误和无效响应体均拒绝，不发送任务，也不自动启动服务争抢端口。
- 仅连接请求失败时尝试启动项目服务。默认启动沿用现有项目入口与权限，并按已验证的本机地址设置主机和端口。
- 同一 MCP 实例的并发请求共享初始探测、启动和就绪轮询；本次完成或失败后清除在途记录，后续请求重新验证服务。诊断使用稳定提示，不透传连接或启动异常中的原始内容。

## 兼容与边界

协议兼容性按整数 `protocolVersion: 1` 判断，不要求发布版本字符串完全相等，未来使用同一协议的不同发布版本仍可连接。v0.5.2 及更早的后台没有新服务标记，需要停止并重新启动当前项目服务。插件资源保留 v0.5.2 及所有更早的 URI 别名，供缓存的旧入口读取当前资源；后台本身仍须更新并重启。

服务标记用于检测误连，不是身份认证。同一 MCP 实例能够合并一次检测与启动；不同 MCP 进程仍可能同时启动，同端口的失败实例通过先绑定再恢复状态保护已有快照，不能据此宣称全局只会启动一次。

本轮没有建立跨端口共用同一状态文件的进程锁，一个项目应只运行一个后台实例。没有新增强制解除清理屏障、自动提高预算或自动恢复真实执行的入口。
