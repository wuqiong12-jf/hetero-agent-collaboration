# 预算设置与多窗口保存

返回[项目首页](../README.md)。

在「恢复与进度」中展开「预算与返工上限」，可以调整监工、工作者和各模型提供方的自动调用上限。「同时只读智能体上限」控制同一目录的只读执行数量；写入执行仍独占目录。

修改数字后，按 **Enter** 或把焦点移到该设置之外即可保存。自动核查、自动派单的开关在点击后保存。保存期间暂时禁用相关操作，避免重复提交。

## 两个窗口同时修改时

窗口会记住开始编辑时的设置值。保存前，后台核对这项设置是否仍是原值，避免较旧的输入直接覆盖另一个窗口的新设置。

例如，两个窗口都看到工作者调用上限为 16。窗口 A 保存为 20 后，窗口 B 原本填写的 24 不会自动覆盖它。B 会保留输入，并提示服务当前值已经变化。

遇到冲突时：

1. 先核对提示中的当前值，按需记下自己填写的数字。
2. 点击「采用最新值」，放弃这项未保存输入，采用界面当前读取到的服务值。
3. 如果仍要调整，再输入新数字并保存。这次会按新的基础值核对。

原生侧面板通过轮询获取状态，另一个窗口的更改可能稍后才显示。保存失败后会额外读取一次当前设置；若读取也失败，先等到当前值更新后再操作，后台仍会拒绝过期的保存请求。

**不同设置可以分别保存。** 一个窗口调整监工预算，另一个窗口调整 DeepSeek 预算时，两项更改会保留。Codex 和 DeepSeek 的预算也分别核对。智能体输出、用量计数和其他设置的更新不会使这项输入产生冲突。

## 保存失败与输入保留

输入为空、不是整数或超出允许范围时，界面保留输入并提示原因。连接或保存请求失败时，可以点击「重试保存」，也可以「采用最新值」后重新填写。若服务已保存但响应没有送达，下一次状态更新可能显示冲突；先核对服务值再决定是否重改。

未保存输入只保留在当前弹窗内，**不是持久保存的草稿**。关闭弹窗或重新加载界面会丢弃尚未保存的输入。已经发出的保存请求可能仍会完成；重新打开后以服务显示的值为准。

允许范围如下：

| 设置 | 允许范围 |
| --- | --- |
| 同时只读智能体上限 | 1–4 |
| 监工、工作者自动调用上限 | 各 1–2000 |
| Codex、DeepSeek 自动调用上限 | 各 1–2000 |
| 工作者额外返工上限 | 0–20 |
| 核查额外调用上限 | 0–10 |

真实模式中，新的只读并行上限不能小于当前仍占用名额的只读执行数量。请等待相关执行结束后再降低。

## 上限与已用次数

调整预算会保留已用调用次数、任务输出和现有工作进度，不会返还已经消耗的调用。上限影响后续自动协作能否继续；修改设置不会重新运行已完成任务。协作正在运行时，成功保存的自动核查、派单或预算设置会参与接下来的调度。

这些数字是**本轮自动协作的调用次数上限**，不是精确的 Codex／ChatGPT 订阅额度，也不是 API 费用上限。模型、思考程度和一次调用的工作量都可能影响实际消耗。手动聊天单独计量，不由这些自动调用上限统一限制。

## 接入方：按修改字段核对

`settings` 操作支持可选的 `expectedSettings`。它与 `settings` 使用相同结构，必须包含完全相同的叶子字段；值为读取时的旧设置。示例：

```json
{
  "action": "settings",
  "settings": {
    "maxWorkerCalls": 24,
    "maxProviderCalls": { "deepseek": 30 }
  },
  "expectedSettings": {
    "maxWorkerCalls": 16,
    "maxProviderCalls": { "deepseek": 16 }
  }
}
```

后台在同一设置操作中完成验证和核对。无效值、未知字段、空补丁或预期字段不一致返回 `400`；任一预期值与当前值不符返回 `409`，整个补丁不生效，也不会由这次请求启动模型。实际接入还应携带读取状态得到的 `expectedStateId`，避免跨会话提交。

核对依据是字段当前值，不是字段的编辑历史：某项从 16 改为 20、再改回 16 后，预期 16 的请求仍可能通过。为兼容旧接入，省略 `expectedSettings` 的请求保持原有更新方式，不受这项并发核对保护。
