## 目录绑定能解决什么

从 v0.6.3 开始，保存的任务、会话、草稿和预算与实际目录一起保存。后台启动时先把配置路径解析为存在的实际目录，再检查快照绑定；另一个目录不能加载这份任务。目录不存在、文件代替目录、绑定无效或不匹配时停止恢复，保留原文件，不创建新演示状态覆盖它。

同一实际目录的路径别名可以恢复。保存的是实际路径，原目录后来改成指向另一个目录的链接时不能把旧绑定一起带过去。损坏 JSON、读取失败或状态结构无效也会停止，不会用新演示会话覆盖它；先保留原文件和备份后再检查。目录绑定不提供文件内容身份、服务认证或沙箱权限；它用于识别协作上下文。

**原生项目切换不会自动改变这个目录。** 当前后台仍固定管理一份协作状态；处理另一个项目时，需要为它使用独立状态。以后再完善原生项目和协作历史的直接关联。

## 为另一项目准备独立状态

先暂停工作，确认运行与清理结束，然后停止当前后台。目录必须已经存在。示例：

```powershell
$env:RELAY_WORKSPACE = 'D:\projects\my-project'
$env:RELAY_STATE_PATH = 'D:\projects\my-project\.relay\state.json'
npm start
```

第一次创建的新状态会绑定该实际目录。不能把原项目的快照直接复制过去当作新状态，也不能通过修改目录环境变量自动重绑定它。返回原协作时，使用原来的目录和原状态文件。

一个状态文件应由一个后台使用。当前没有跨进程快照锁，不要让多个后台同时写同一文件。

## 从旧版本迁移

旧快照没有可靠目录信息，程序无法证明旧任务在哪个目录执行，因此不会猜测当前目录、原生项目或任务正文。需要先明确原目录；如果不确定，可在旧版本后台仍运行时查看实际目录并核对工作，再暂停和关闭它。

**先停止旧服务，并保留原快照备份。** 确认没有运行或停止中的智能体、聊天、任务和清理。暂停后保留交付等待核查的任务可以迁移，不会重新执行工作者。以下命令只给未绑定快照新增目录信息，保留原任务、消息和用量：

```powershell
$stateFile = (Resolve-Path '.relay\state.json').Path
$originalDirectory = 'C:\path\to\original-project'
$snapshotHash = (Get-FileHash -LiteralPath $stateFile -Algorithm SHA256).Hash
node scripts\migrate-workspace.mjs --state $stateFile --workspace $originalDirectory --expected-sha256 $snapshotHash
```

替换 `originalDirectory` 为明确的原任务目录。已有绑定不会被这个命令重新绑定。运行中任务、无有效交付的待核查任务、非空清理屏障、文件哈希变化或文件／父目录重定向都会拒绝；原文件保持。保存使用独占的新临时文件和同目录原子替换，失败不删除目标文件。

工具不提供跨进程锁。哈希和文件身份检查能拒绝观测到的变化，不能防止另一个进程在最后检查后写入，因此停旧服务是必要条件。完成后启动新后台，并在「工作目录」里核对。

本机本轮迁移依据旧服务已核实的实际目录、暂停与持久化状态，保留了旧快照备份，原有四项任务及用量不变；没有恢复执行。完整证据见[本轮记录](runs/2026-10-11-workspace.md)。
